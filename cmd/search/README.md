# Search — KAN-39

Отдельный stateless gRPC-сервис (8088) с API People и Projects. Gateway публикует GET `/api/v1/search/people` и `/api/v1/search/projects`. Search делегирует запросы API владельцев: User.SearchPeople и Project.List. Он не читает их таблицы, не копирует контакты/доказательства и не имеет собственного поискового индекса. Это позволяет позже добавить индекс за тем же контрактом; пока полнотекстовые запросы выполняются PostgreSQL владельцев.

Поиск людей: q, повторяемые skill/interest, university, my_university, open_only, verified_only, verified_projects, publications, project_type scientific/practical. Навыки/интересы и вуз сравниваются без учёта регистра; списки тегов означают «все указанные». my_university требует сеанс и берёт вуз из профиля, а при пустом вузе возвращает пустой результат. verified_projects означает подтверждённые проектные достижения в портфолио, publications — подтверждённые научные работы. Значок verified_only зависит от подтверждённого адреса HSE, не от работ. Возвращаются только активные подтверждённые аккаунты с заполненным именем, без себя и заблокированных в любую сторону. В ответе отдельная Person-карточка, в которой отсутствуют контакты и документы.

Поиск проектов: q, type, field, повторяемый tag, duration (up_to_3m/3_to_6m/over_6m), status, mine (owner/participant), profile_user_id. Приватность и доступ к проектам проверяет Project. Сроки фильтруются по длительности планового интервала; q использует PostgreSQL simple full-text (все слова, без морфологического анализа). Университет/сфера/навыки — точные значения без учёта регистра, не нечёткий поиск.

Оба списка имеют limit 1–100 (по умолчанию 20), offset 0–10000 и total. Без параметров рекомендации не вызываются: поиск и ранжирование рекомендаций имеют разные контракты. Фильтры применяются до пагинации. Без сеанса доступны публичные запросы; credential передаётся владельцам данных и проверяется даже для чтения.

Запуск: `docker compose up --build`, либо POSTGRES_PASSWORD и `go run ./cmd/search -config cmd/search/config.example.yaml`. В конфигурации grpc, peers.user, peers.project, postgres. Общие миграции выполняются при старте, бизнес-таблиц Search не создаёт. HTTP остаётся только в Gateway, gRPC не публикуется наружу.
