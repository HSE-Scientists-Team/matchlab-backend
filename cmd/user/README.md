# Сервис User

User владеет учётными записями, логинами, хешами паролей и принадлежностью адресов электронной почты в схеме PostgreSQL `users`. При регистрации адрес электронной почты не обязателен. Логин при регистрации и входе приводится к нижнему регистру, а сравнение не зависит от регистра. Пароли хранятся как хеши bcrypt. После успешного входа User запрашивает у Auth создание сеанса по gRPC.

## Модель электронной почты

- `user_account.login` уникален без учёта регистра и содержит от 1 до 32 символов ASCII: буквы, цифры, `_`, `-` или `.`. Адрес электронной почты не используется для входа.
- `email_verification_request` хранит один текущий ожидающий подтверждения адрес пользователя и SHA-256-хеш одноразового токена со сроком действия 30 минут. Несколько пользователей могут одновременно запросить один адрес.
- `user_email` хранит только подтверждённые адреса. Уникальный индекс без учёта регистра позволяет закрепить адрес только за одним пользователем. У пользователя может быть один подтверждённый адрес; подтверждение нового адреса заменяет прежний.
- Токен принадлежит пользователю, запросившему подтверждение. Подтверждение токена одного пользователя не подтверждает запрос другого, даже если они указали один адрес. Если другой пользователь подтвердил адрес первым, более поздняя попытка завершается конфликтом, а владелец адреса не меняется.

User передаёт запросы на отправку подтверждений внутреннему gRPC-сервису Mail. Mail сохраняет зашифрованное задание на доставку и повторяет неудачные попытки SMTP. Токены подтверждения принадлежат User; Mail не может подтвердить адрес. Поведение доставки описано в [документации Mail](../mail/README.md).

## PostgreSQL и миграции

Миграции Goose встроены в исполняемый файл сервиса и применяются до запуска gRPC-слушателя. Текущая миграция `00001_create_accounts.sql` создаёт схему `users`, учётные записи, подтверждённые адреса, запросы на подтверждение и доверенные домены. Её откат удаляет эти таблицы и типы вместе с данными; проверяйте последствия перед откатом.

## Локальный запуск

Для запуска всех сервисов выполните `docker compose up --build`. Gateway доступен по адресу `http://localhost:8080`, а письма с подтверждением — в Mailpit по адресу `http://localhost:8025`.

Для прямого запуска Go-сервисов поднимите зависимости и Mailpit через Compose, затем запустите Auth, Mail, User и Gateway с их файлами `config.example.yaml`. Необходимые секреты: `POSTGRES_PASSWORD`, `REDIS_PASSWORD` (только Auth), `MAIL_ENCRYPTION_KEY`, `SMTP_USERNAME` и `SMTP_PASSWORD` (Mail). Для локальной разработки сначала выполните `docker compose up -d postgres redis mailpit`. Compose привязывает порты сервисов только к localhost. Ключ шифрования Compose и настройки SMTP Mailpit предназначены только для разработки.

## Внутренний gRPC API

- `Register(login, password)` создаёт активную учётную запись без адреса электронной почты.
- `Login(login, password)` проверяет учётные данные и возвращает сеанс.
- `RequestEmailVerification(user_id, email)` заменяет ожидающий запрос пользователя и отправляет письмо для подтверждения.
- `ConfirmEmail(token)` подтверждает и закрепляет адрес, если он ещё не принадлежит другому пользователю.
- `GetEmailStatus(user_id)` возвращает `not_set`, `pending` или `verified`, а также текущий и ожидающий подтверждения адреса.

Проверка: `go test ./internal/user/...`. Интеграционный тест Goose использует настоящий PostgreSQL и проверяет правило «несколько ожидающих запросов, один подтверждённый владелец»: `go test -tags=integration ./internal/user/migrations`.
