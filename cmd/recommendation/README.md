# Recommendation — KAN-39

Отдельный stateless gRPC-сервис (8089), методы People и Projects, HTTP GET `/api/v1/recommendations/people` и `/api/v1/recommendations/projects` через Gateway. Оба требуют действительный сеанс с подтверждённой почтой.

Сервис читает периодически рассчитанные ранжированные ID из отдельного Redis. Python-модуль `ml/matchlab_ml` содержит baseline по навыкам/интересам и hybrid (TF-IDF + близость истории откликов). Также есть learned: отдельные обучаемые ранжировщики проектов и людей с loss по эпохам в MLflow. Для людей сигналом служат заявки на общие проекты, а не личные симпатии. По умолчанию публикуется baseline; hybrid и learned считаются для сравнения. При недостатке данных learned использует baseline. Scores — внутренние оценки, не вероятность успеха и не проценты совпадения. limit 1–100, по умолчанию 20; offset не поддерживается.

В Redis нет карточек: только ID, score, role_id и факторы совпадения. User.GetProfile и Project.Get возвращают актуальные данные; CheckInteraction проверяет блокировки в обе стороны. Люди должны иметь активный подтверждённый аккаунт и открытый непустой профиль; проекты — публичный открытый набор со свободным местом, не собственные и без текущего участия пользователя. Перед выдачей проверяется не более 2×limit кешированных кандидатов, одновременно не более восьми. При недоступном владельце данных возвращается ошибка, а не устаревшая карточка.

Нет кеша, пользователь новый, запись истекла или Redis недоступен — используется случайный допустимый каталог через Search. Нехватка актуальных кандидатов также дополняется каталогом; результат может быть короче limit. total остаётся количеством результатов каталога до случайной выборки, а не числом персональных совпадений; для проектов дополнительная проверка вместимости/блокировок может уменьшить выдачу. Повторы между запросами возможны. HTTP-ответ получает необязательный объект `recommendation` с версиями, временем снимка и факторами по ID. Внутренний gRPC сохраняет прежние сообщения, provenance передаётся в бинарном заголовке `matchlab-recommendations-bin`; Gateway преобразует его в JSON.

Зависимости: Recommendation → User, Project, Search; Search → User/Project. Чтения бизнес-таблиц в онлайн-сервисе нет. Batch отдельно использует минимизированные версионированные export views миграции 00008 и reader-роль. PostgreSQL онлайн-сервису нужен для общего startup migration runner.

Обычный запуск `docker compose up --build` сохраняет catalogue fallback без ML-инфраструктуры. YAML: grpc, peers.user, peers.search, peers.project, postgres. Для включения кеша добавьте peers.recommendation_redis (host:port) и секрет RECOMMENDATION_REDIS_PASSWORD. Auth Redis не используйте: кеш рекомендаций должен жить отдельно.

Полный локальный ML/BI Compose находится в `matchlab-infra/compose/ml` соответствующей feature-ветки. Airflow вызывает те же Python-функции, что CLI. Зависимости Python нужны только batch-контейнерам, не Go-сервисам.

Проверки: `go test ./internal/recommendation ./internal/gateway/delivery/http`; Python: `PYTHONPATH=ml python3 -m unittest discover -s ml/tests -v` (Python 3.10+).
