# Recommendation — KAN-39

Отдельный stateless gRPC-сервис (8089), методы People и Projects, HTTP GET `/api/v1/recommendations/people` и `/api/v1/recommendations/projects` через Gateway. Оба требуют действительный сеанс с подтверждённой почтой.

Текущая стратегия — случайная выборка всего доступного множества через Search; PostgreSQL владельца данных делает ORDER BY random() до LIMIT. Это временная стратегия для небольшого каталога: она не оценивает сходство, не выдаёт проценты совпадения и не обещает ML-персонализацию. Внутри одной выдачи нет дублей; между запросами повторы возможны. limit 1–100, по умолчанию 20; offset не поддерживается. total — размер допустимого множества до случайной выборки.

Люди: только открытые к сотрудничеству профили, исключая себя и взаимные блокировки. Проекты: только публичный открытый набор, исключая собственные проекты и проекты, где пользователь уже состоит. Нельзя обойти права через рекомендации: фильтрацию выполняют User и Project. При недоступной зависимости сервис возвращает ошибку, а не подставляет фиктивные данные.

Зависимости направлены Recommendation → Search → User/Project. Recommendation отдельно обращается к User.GetIdentity для проверки сеанса. Владельцы данных не вызывают рекомендательную систему; циклических зависимостей и чтения чужих таблиц нет. Собственной БД рекомендаций или кэша пока нет; PostgreSQL нужен только для общего startup migration runner.

Запуск: `docker compose up --build`, либо POSTGRES_PASSWORD и `go run ./cmd/recommendation -config cmd/recommendation/config.example.yaml`. YAML: grpc, peers.user, peers.search, postgres.
