# Migrator

Одноразовая джоба применяет SQL-миграции PostgreSQL через Goose и завершает работу. Она не обслуживает запросы. Успешный выход имеет код `0`; ошибка подключения или миграции — ненулевой код. В Docker Compose включён `restart: on-failure`, а User и Media ждут успешного завершения джобы.

Миграции хранятся в [`internal/migrator/migrations`](../../internal/migrator/migrations) и встраиваются в бинарный файл. Общая история Goose для User и Media находится в `users.goose_db_version`; актуальная версия — `2`.

| Миграция | Результат Up | Результат Down |
| --- | --- | --- |
| `00001_create_accounts.sql` | Схема User: аккаунты, подтверждённые адреса, заявки и разрешённые домены | Удаление четырёх таблиц User и его enum-типов |
| `00002_create_media_files.sql` | `media.file`, статусы, ограничения и индексы; `is_public NOT NULL DEFAULT false` | Удаление таблицы файлов и `media.file_status` |

Один шаг Down откатывает только последнюю миграцию: с версии `2` до `1` удаляются метаданные Media, а данные User сохраняются. Второй шаг удаляет таблицы User и возвращает версию `0`. Откат удаляет данные PostgreSQL; объекты в S3 он не удаляет. Поэтому Down не является способом обычного обновления работающей установки. Процесс Migrator выполняет только Up.

Новая БД получает обе миграции. Повторный Up сохраняет данные и ничего не меняет, если версия уже `2`. Тестовые домены HSE не входят в миграции: их добавляют отдельно [локальным seed-скриптом](../user/README.md). Целевая DBML-модель не является SQL-миграцией.

## Обновление уже существующей локальной БД

На текущем этапе разработки `is_public` добавлен в существующую миграцию `00002`. Если она уже применена, пересборка Migrator и повторный Up не добавят колонку. Для локальной БД с актуальной остальной схемой выполните однократно:

```sql
ALTER TABLE media.file
ADD COLUMN IF NOT EXISTS is_public boolean NOT NULL DEFAULT false;
```

Существующие файлы останутся приватными. Если колонка уже есть, команду повторять не нужно. Это изменение не требует удаления тома PostgreSQL или сброса истории Goose. Для других изменений уже применённой схемы используйте новые миграции с Up/Down; не исправляйте историю Goose вручную. Установки со старой схемой User до регистрации через заявки требуют отдельного плана обновления.

Для локального запуска вместе с сервисами используйте `docker compose up --build`. Повторный запуск джобы с актуальными встроенными файлами: `docker compose run --rm --build migrator`. Логи: `docker compose logs migrator`. Не запускайте два экземпляра мигратора для одной базы одновременно. Если миграция постоянно падает, Compose будет повторять попытки: исправьте причину, прежде чем запускать User и Media.

Конфигурация читается из YAML (`-config`, по умолчанию `/etc/app/config.yaml`); пример — [`config.example.yaml`](config.example.yaml). Пароль задаётся только через `POSTGRES_PASSWORD`. Для независимой выкладки сервисов сначала применяйте совместимые миграции, затем обновляйте затронутые сервисы; удаление старых столбцов выполняйте после перехода всех потребителей.

## Проверка

Обычная проверка сборки: `go test ./internal/migrator/...`. Проверки SQL работают с отдельными контейнерами PostgreSQL и требуют запущенный Docker:

```sh
go test -tags=integration -count=1 -v ./internal/migrator/migrations
```

- `TestUsersSchema`: таблицы User, ограничения email, заявки без аккаунта, принадлежность подтверждённого адреса и отсутствие автоматических тестовых доменов.
- `TestMediaSchema`: приватность и pending по умолчанию, сохранение публичности, запрет NULL, уникальность объекта и ограничения метаданных.
- `TestMigrationsApplyAndStayCurrent`: версия `2`, повтор без потери данных, откат Media с сохранением User, полный откат и повторное создание схем.

Запуск одной проверки:

```sh
go test -tags=integration -count=1 -v ./internal/migrator/migrations -run '^TestMediaSchema$'
```

Тесты не подключаются к БД Compose. Они выполняются последовательно внутри пакета, поскольку настройки Goose глобальные. Разные запуски тестов используют разные контейнеры. Настройка Docker Desktop для Windows описана в [README Media](../media/README.md).
